# Optimization Principles - MANDATORY

**These principles are NON-NEGOTIABLE. Every operation in thesun and every MCP it generates MUST follow them.**

## Core Rule: NEVER Sequential When Parallel Is Possible

```
❌ FORBIDDEN                          ✅ REQUIRED
─────────────────────────────────     ─────────────────────────────────
for (const mcp of mcps) {             await Promise.all(mcps.map(mcp =>
  await analyze(mcp);                   analyze(mcp)
}                                     ));

for (const check of checks) {         await Promise.all([
  await runCheck(check);                runPerfCheck(),
}                                       runSecCheck(),
                                        runFeatureCheck(),
                                      ]);

await step1();                        // Only sequential if step2 DEPENDS on step1
await step2();                        // Otherwise, run in parallel
await step3();
```

```typescript

await discover(tool1);
await discover(tool2);
await generate(tool1);

await Promise.all([
  discover(tool1),
  discover(tool2),
```

```typescript

const [hasPackage, hasBuild, hasTests] = await Promise.all([
  checkPackageJson(),

  checkTests(),
]);
```

## Generated MCP Requirements

Every MCP generated by thesun is Python/FastMCP, streamable-http transport only (never stdio, never SSE). It MUST include:

### 1. Browser-Fingerprint HTTP Client (MANDATORY — copied template, never hand-rolled)
Copy `src/templates/python/http_client.py` verbatim into every generated server. It supplies connection reuse (curl_cffi session) AND a wire-verified Chrome-on-Linux TLS/HTTP-2 fingerprint — a bare `httpx.AsyncClient()` or `requests` session satisfies neither requirement.
```python
from http_client import build_http_client

client = build_http_client(base_url="https://api.example.com")
```

### 2. Singleton Client Pattern (MANDATORY)
```python
_client: httpx.AsyncClient | None = None

async def get_client() -> httpx.AsyncClient:
    global _client
    if _client is None:
        _client = build_http_client(base_url=BASE_URL)
    return _client
```

### 3. Auth via the Copied `auth.py` Template (MANDATORY — never hand-rolled)
Copy `src/templates/python/auth.py` verbatim. It already caches nothing itself but resolves the credential fresh via Hermes (which owns caching/refresh) or a standalone env var — do not add a second, competing token-cache layer on top of it.
```python
from auth import get_auth_headers

headers = await get_auth_headers()
```

### 4. Rate Limiting + Backoff via the Copied `ratelimit.py` Template (MANDATORY)
Every outbound call MUST go through `request_with_backoff()`, not a bare `client.request(...)`. This is also what makes response-side 429/503 handling and Retry-After compliance automatic — do not hand-roll a second retry loop.
```python
from ratelimit import AdaptiveRateLimiter, request_with_backoff

limiter = AdaptiveRateLimiter(per_minute=60, max_concurrency=10)  # seed from detected/known limits
resp = await request_with_backoff(client, "GET", "/data", limiter)
```

### 5. Parallel Batch Operations (MANDATORY for bulk tools)
```python
import asyncio

async def batch_operation(items: list, operation, concurrency: int = 10) -> list:
    results = []
    for i in range(0, len(items), concurrency):
        chunk = items[i : i + concurrency]
        results.extend(await asyncio.gather(*(operation(item) for item in chunk)))
    return results

# Usage in a tool
async def bulk_get(ids: list[str]) -> list[dict]:
    return await batch_operation(ids, fetch_item)
```

### 6. NO Shell Spawning (FORBIDDEN)
```python
# ❌ ABSOLUTELY FORBIDDEN — spawning shell processes (subprocess, os.system, curl, wget, etc.)
# This creates 100x+ overhead compared to native HTTP, and cannot carry the browser fingerprint.

# ✅ REQUIRED: the templated HTTP client
resp = await request_with_backoff(client, "GET", "/data", limiter)
```

## Validation Checklist

Before any MCP is considered complete, verify — **and then run `thesun verify <output_dir>` (the Conformance Lab hard gate), which asserts several of these on the actual wire bytes rather than by grep:**

| Check | Required | How to Verify |
|-------|----------|---------------|
| Templated HTTP client (browser fingerprint) | ✅ | `grep -r "build_http_client" src/server.py` |
| Singleton client | ✅ | `grep -r "_client.*None" src/` |
| Auth via `auth.py` | ✅ | `grep -r "get_auth_headers" src/` |
| Rate limiter + backoff wired in | ✅ | `grep -r "request_with_backoff" src/` |
| No shell spawning | ✅ | `grep -r "subprocess\.\|os\.system(" src/` returns nothing |
| Batch operations | ✅ (if bulk tools) | `grep -r "asyncio.gather" src/` |
| Wire fingerprint == Chrome-on-Linux | ✅ | `thesun verify` wire-fingerprint gate (not greppable — requires the Lab) |
| Rate-limiter presence for known-limited targets | ✅ | `thesun verify` rate-limiter-presence gate |

## Performance Targets

| Metric | Target | Unacceptable |
|--------|--------|--------------|
| Tool call latency | < 500ms | > 2s |
| Bulk operation (100 items) | < 5s | > 30s |
| Startup time | < 1s | > 3s |
| Memory usage | < 100MB | > 500MB |

## When Updating MCPs

The `update-mcps` skill MUST:

1. **First**: Check for optimization anti-patterns
2. **Fix**: Any violations of these principles
3. **Measure**: Before/after performance
4. **Report**: Performance improvements

Performance optimization is **CRITICAL priority** - same level as security vulnerabilities.

## Enforcement

These principles are enforced by:
1. `mcp-builder` agent - Generates optimized code from start
2. `validator` - Checks for optimization patterns
3. `mcp-updater` - Fixes violations in existing MCPs
4. Code review - Rejects MCPs that violate principles
